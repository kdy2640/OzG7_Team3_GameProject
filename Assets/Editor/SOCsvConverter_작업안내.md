# SO ↔ CSV 변환기 작업 안내

## 목적

프로젝트에 쌓인 여러 `ScriptableObject` 데이터를 기획자가 CSV에서 한꺼번에 확인하고 수정할 수 있도록 Editor 전용 변환기를 완성한다. 단순히 동작하는 코드를 만드는 것뿐 아니라, 데이터가 **선택 → 변환 → 검증 → 저장**되는 흐름을 이해하는 것이 작업의 핵심이다.

## 작업 범위

- 작업 파일: `Assets/Editor/SOCsvConverter.cs`
- `SOCsvExporterWindow.cs`는 완성된 UI이므로 원칙적으로 수정하지 않는다.
- Window가 호출하는 기존 메서드의 이름, 매개변수, 반환 타입은 유지한다.
- 타입별 CSV는 `{저장 폴더}/{SO타입명}.csv` 한 파일로 관리한다.
- CSV의 첫 번째 열인 `ObjectName`을 SO 이름이자 고유 키로 사용한다.

지원 타입은 `string`, `char`, 숫자, `bool`, `enum`으로 제한한다. 배열, `List`, 사용자 정의 class/struct, `Sprite`, `GameObject`, 다른 SO 등의 참조형 필드는 CSV에서 제외하고 Import할 때도 기존 값을 보존한다.

## 구현 방향

1. `GetSupportedFields`를 구현해 Window에 지원 필드가 표시되게 한다.
2. `SerializeValueForCsv`를 구현해 SO 값이 올바른 문자열로 표시되게 한다.
3. `ExportToCSV`를 구현해 여러 SO를 하나의 CSV로 저장한다.
4. `ParseCsv`를 구현해 쉼표·큰따옴표·줄바꿈이 포함된 셀도 읽을 수 있게 한다.
5. `ImportFromCSV`를 구현해 기존 SO를 갱신하고 없는 SO를 생성한다.

CSV 열의 순서가 바뀌어도 헤더 이름으로 필드를 찾아야 한다. 숫자는 PC 언어 설정에 영향받지 않아야 하며, 잘못된 행이 있으면 일부 SO만 변경된 상태로 끝나지 않도록 실제 수정 전에 전체 데이터를 검증한다.

## 금지사항

- 런타임 스크립트나 기존 데이터 SO 타입을 변경하지 않는다.
- 새로운 패키지, 외부 CSV/JSON 라이브러리, 범용 프레임워크를 추가하지 않는다.
- 타입별 예외 처리 코드를 하드코딩하지 않는다.
- 리스트나 Unity 참조형 지원으로 임의 확장하지 않는다.
- CSV에 없는 SO를 삭제하거나, CSV에 없는 필드 값을 초기화하지 않는다.
- 이해하거나 설명할 수 없는 코드를 그대로 제출하지 않는다.

## 완료 조건

- SO 타입 선택 후 지원 필드와 현재 값이 Window에 표시된다.
- Export한 CSV를 수정한 뒤 Import하면 해당 SO 값이 반영된다.
- enum은 이름으로 저장되며 문자열, 숫자, bool이 원래 타입으로 복원된다.
- 쉼표, 큰따옴표, 줄바꿈이 포함된 문자열이 왕복 보존된다.
- 중복 `ObjectName`, 잘못된 숫자·enum, 손상된 CSV는 명확한 오류로 중단된다.
- 신규 SO 생성, 기존 SO 갱신, 에셋 저장이 정상 동작한다.
- 직접 수행한 정상·실패 테스트와 현재 구현의 한계를 설명할 수 있다.

## AI 사용

AI와 검색 도구 사용은 허용한다. 단, 제출한 모든 코드는 본인이 설명하고 수정할 수 있어야 한다. 사용한 AI 결과 중 그대로 채택한 부분, 직접 수정한 부분, 잘못되어 버린 제안을 간단히 기록한다. 리뷰 중 코드 설명이나 작은 요구사항 변경에 대응하지 못한 부분은 미완료로 판단한다.
